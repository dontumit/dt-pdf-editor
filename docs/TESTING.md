# การทดสอบระบบ

ระบบมีชุดทดสอบสองชุดที่รันได้จริงกับเซิร์ฟเวอร์ที่กำลังทำงานอยู่

| ชุด | ทดสอบอะไร | ต้องใช้ |
|---|---|---|
| `tests/api.mjs` | API, ความปลอดภัย, สิทธิ์, งานฝั่งเซิร์ฟเวอร์ | Node.js เท่านั้น |
| `tests/e2e.mjs` | UI จริงผ่านเบราว์เซอร์จริง ตั้งแต่เลือกไฟล์จนดาวน์โหลด | Playwright + Chromium |

## วิธีรัน

```bash
# 1) เปิดเซิร์ฟเวอร์ไว้ก่อน
cd server && npm start

# 2) ทดสอบ API (อีกหน้าต่างหนึ่ง)
BASE_URL=http://localhost:8080 ADMIN_PASSWORD=<รหัสผ่านผู้ดูแล> node tests/api.mjs

# 3) ทดสอบผ่านเบราว์เซอร์
cd tests && npm run setup      # ติดตั้ง playwright + chromium (ครั้งแรกเท่านั้น)
BASE_URL=http://localhost:8080 node e2e.mjs
```

ชุด e2e จะสร้างโฟลเดอร์ชั่วคราวเก็บไฟล์ผลลัพธ์ไว้ให้ตรวจสอบด้วยตนเอง
และบันทึกภาพหน้าจอของกรณีที่ไม่ผ่านไว้ในโฟลเดอร์เดียวกัน

> **หมายเหตุเรื่องโควตา:** ชุด e2e ใช้งานหลายครั้งติดกันจนอาจชน rate limit ของผู้ใช้ทั่วไป
> ก่อนทดสอบให้เข้า `/admin` แล้วตั้ง `RATE_LIMIT_GUEST` เป็น 500 ชั่วคราว

## ผลการตรวจสอบคุณภาพไฟล์ผลลัพธ์

ตรวจด้วย `pdftotext`, `pdfinfo`, `qpdf` และการเรนเดอร์เป็นภาพเพื่อดูด้วยตา

| สิ่งที่ตรวจ | ผล |
|---|---|
| ลายน้ำภาษาไทย "เอกสารลับ ห้ามเผยแพร่" | สระและวรรณยุกต์วางถูกตำแหน่ง หมุน 45 องศาและอยู่กึ่งกลางหน้า |
| เลขหน้าเลขไทย | ได้ `หน้าที่ ๑` `หน้าที่ ๒` … ถูกต้องครบทุกหน้า |
| ข้อความไทยในหน้าแก้ไข | `ผู้ป่วยชื่อ นายทดสอบ ระบบไทย ๒๕๖๙` ตัดบรรทัดและแสดงผลถูกต้อง |
| ใส่รหัสผ่าน PDF | `qpdf --show-encryption` รายงาน R=6 (AES-256) และสิทธิ์ตรงกับที่เลือก |
| เปิดไฟล์ที่ล็อกโดยไม่ใส่รหัส | ถูกปฏิเสธ (`Incorrect password supplied`) |
| PDF เป็น Word | ข้อความถูกดึงครบ แบ่งย่อหน้าและตัดหน้าถูกต้อง ไฟล์เป็น .docx จริง |
| จัดหน้า PDF | 12 หน้า เหลือ 11 หน้าหลังลบ และค่า `/Rotate 90` ถูกบันทึกลงไฟล์ |
| รวมไฟล์ | 3 + 2 หน้า ได้ผลลัพธ์ 5 หน้าตามลำดับที่จัดไว้ |

### การลดขนาดเอกสาร (ทดสอบกับไฟล์สแกน 6 หน้า 1.43 MB)

| โหมด | ขนาดผลลัพธ์ | ลดลง | หมายเหตุ |
|---|---|---|---|
| อัตโนมัติ | 0.52 MB | 63.5% | ลองแบบคงข้อความก่อน แล้วเปลี่ยนเป็นแปลงภาพให้เอง |
| คงข้อความ | 1.43 MB | 0.1% | ถูกต้อง — ไฟล์นี้เป็นภาพล้วน ไม่มีโครงสร้างให้ลด |
| ลดให้เล็กที่สุด | 0.52 MB | 63.5% | |
| กำหนดเป้า 0.5 MB | 0.38 MB | 73.2% | ไล่ลดคุณภาพจนได้ตามเป้า |

เปรียบเทียบภาพก่อน–หลังที่ 73% แล้ว ความคมชัดของข้อความยังอ่านได้ชัดเจนเท่าเดิม

ทดสอบกับไฟล์ที่บีบอัดมาแล้ว ระบบคืนไฟล์ต้นฉบับพร้อมข้อความอธิบาย
แทนที่จะสร้างไฟล์ที่ใหญ่ขึ้นและคุณภาพแย่ลง — พฤติกรรมเดียวกันนี้ใช้กับการลดขนาดรูปภาพด้วย

## ข้อบกพร่องที่พบระหว่างทดสอบและได้แก้แล้ว

ทั้งหมดนี้พบจากการทดสอบจริง ไม่ใช่การตรวจโค้ดด้วยสายตา

| ปัญหา | สาเหตุ | การแก้ |
|---|---|---|
| ภาษาไทยใน PDF กลายเป็น `?` | `@pdf-lib/fontkit` เวอร์ชัน ESM มี bare import ของ `pako` ที่เบราว์เซอร์ resolve ไม่ได้ ระบบจึง fallback ไปฟอนต์มาตรฐานเงียบ ๆ | เปลี่ยนไปใช้เวอร์ชัน UMD แล้วห่อเป็น ES module ผ่าน `scripts/build-vendor.mjs` |
| ลดขนาด PDF แล้วได้ไฟล์ 0 ไบต์ | pdf.js ย้าย (transfer) `ArrayBuffer` ไปให้ worker ทำให้ตัวแปรเดิมถูก detach ตอนคืนไฟล์ต้นฉบับ | สำเนาไบต์ต้นฉบับไว้ก่อนส่งให้ pdf.js |
| ลดขนาดรูป PNG แล้วไฟล์ใหญ่ขึ้น 321% | การเข้ารหัส PNG ใหม่จาก canvas ใหญ่กว่าเดิมเมื่อเป็นภาพสีเรียบ | คืนไฟล์ต้นฉบับเมื่อผลลัพธ์ไม่เล็กลง พร้อมแนะนำให้เปลี่ยนเป็น JPG/WEBP |
| ลายน้ำที่หมุนหลุดออกนอกหน้ากระดาษ | pdf-lib หมุนรอบจุดเริ่มต้น ไม่ใช่จุดกึ่งกลาง | เพิ่ม `resolveRotatedPosition()` คำนวณกรอบหลังหมุนแล้วถอยกลับหาจุดเริ่มต้น |
| สถิติผู้เข้าชมถูกปฏิเสธด้วย 403 | `navigator.sendBeacon` แนบ header เองไม่ได้ คำขอจึงไม่ผ่าน CSRF | เปลี่ยนไปใช้ `fetch` พร้อม `keepalive: true` |
| ข้อความในช่องค้นหาทับไอคอนแว่นขยาย | กฎ `input[type="search"]` ทั่วไปมีความเฉพาะเจาะจงเท่ากันแต่อยู่ท้ายไฟล์ จึงทับ padding ของช่องค้นหา | เพิ่มความเฉพาะเจาะจงของ selector |
| ข้อความแจ้งเตือน (toast) บังปุ่มด้านล่าง | `.toast` ตั้ง `pointer-events: auto` ทับพื้นที่ปุ่มหลักบนมือถือ | ให้เฉพาะปุ่มภายใน toast รับการกด ตัวการ์ดไม่รับ |
| หน้าต่างกู้คืนงานเด้งขัดจังหวะกลางคัน | ตรวจงานค้างทุกหน้าและถามซ้ำทุกครั้งที่เปิดเว็บ | ถามเฉพาะบนหน้าแรก ถามครั้งเดียวต่องาน และลบโปรเจกต์ว่างทิ้งอัตโนมัติ |
| ชื่อระบบกับคำโปรยอยู่บรรทัดเดียวกัน | `.brand__title` เป็น `display: inline` จึงไหลต่อกันเมื่อชื่อสั้น | กำหนดเป็น `display: block` |
| เครื่องหมายถูกในช่องติ๊กหายไป | ฟอนต์ที่ subset แล้วอาจไม่มีอักขระเครื่องหมายถูก | วาดด้วยเส้นตรงสองเส้นแทนการใช้อักขระ |

## การทดสอบด้วยตนเองที่ควรทำก่อนเปิดใช้จริง

ชุดทดสอบอัตโนมัติครอบคลุมการทำงานหลัก แต่สิ่งเหล่านี้ต้องลองด้วยตนเอง

- [ ] เปิดจากแอป LINE จริงบนมือถือ — ตรวจว่าเข้าสู่ระบบอัตโนมัติและกลับหน้าเดิมได้
- [ ] ทดสอบกล้องสแกนบนมือถือจริง ทั้ง iOS และ Android (ต้องใช้ผ่าน HTTPS)
- [ ] ทดสอบไฟล์ใหญ่จริงจากงานประจำวัน (50 MB ขึ้นไป, 200 หน้าขึ้นไป)
- [ ] ทดสอบเอกสารสแกนภาษาไทยจริงกับ OCR แล้วดูความแม่นยำ
- [ ] ทดสอบ PDF ที่มีรหัสผ่านและ PDF ที่เสียหาย ว่าข้อความ error เข้าใจง่าย
- [ ] ปิดอินเทอร์เน็ตหลังเปิดเว็บแล้ว ลองใช้เครื่องมือที่ทำงานบนเครื่อง
- [ ] ติดตั้งเป็นแอป (Add to Home Screen) แล้วเปิดจากไอคอน
- [ ] เปิดพร้อมกันหลายเครื่องแล้วดูตัวเลขผู้ใช้ออนไลน์ที่ `/admin`
- [ ] ปล่อยไฟล์งานฝั่งเซิร์ฟเวอร์ทิ้งไว้เกิน 30 นาที แล้วตรวจว่าถูกลบจริง

## เครื่องมือช่วยตรวจสอบในระบบ

ระบบมีปุ่มตรวจสอบความพร้อมในตัวที่ **ตั้งค่า → ตรวจสอบความพร้อมของระบบ**
ตรวจให้ทีละรายการว่า Web Worker, ไลบรารี PDF, ฟอนต์ไทย, Canvas, IndexedDB,
Service Worker, กล้อง และเครื่องมือฝั่งเซิร์ฟเวอร์แต่ละตัวพร้อมใช้งานหรือไม่
เหมาะกับการตรวจหลังติดตั้งเสร็จ หรือเมื่อผู้ใช้แจ้งว่าภาษาไทยแสดงผลผิด
